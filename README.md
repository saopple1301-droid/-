# 電子レンジ対応 非接触中心温度推定センサー — モデル構築

## これは何を使っているか

`train_model.py` は **Pythonの標準ライブラリだけ**で動く重回帰(最小二乗法)スクリプトです。
numpyやscikit-learnのインストールは不要です(データ数が数十件と少なく、
単純な線形回帰で十分なため、あえて外部ライブラリに依存させていません)。

やっていることは中学〜高校レベルの数学で説明できます。

- 「中心温度 = a×表面温度 + 切片」という直線の式の a と切片を、実測データに
  一番よく当てはまるように求める(最小二乗法)。中学校で習う y = ax + b と同じ考え方。
- 現在は**冷凍ハンバーグ(`hamburger_nichirei_mini`)のデータだけ**を使ってモデルを作る(既定動作)。
  CSVにはコロッケのデータも含まれているが、今回はハンバーグに対象を絞ったためスコープ外として
  除外している。コロッケも含めたい場合は `python3 train_model.py --categories all` を指定する。
- 特徴量(モデルへの入力)は既定で**表面温度のみ**。データが8件しかなく、
  特徴量を増やすほど過学習(たまたま今回のデータに合っただけの式になる)のリスクが
  高まるため、シンプルな単回帰を既定にしている。

## 使い方

```bash
python3 train_model.py
```

`data/measured_data_trial1.csv` を読み込み、カテゴリごとの係数とR²(当てはまりの良さ、
1に近いほど良い)をターミナルに表示し、`model_coefficients_sample.h`(C++ヘッダ)を
自動生成します。ファームウェア(`center_temp_sensor.ino`)側はこのヘッダの係数を
読んで中心温度を計算する想定です。

既定の実行結果は `center_temp = 10.78 + 1.033 × surface_temp_mean`(R²=0.858、n=8)です。
これは冷凍ハンバーグ(ニチレイ ミニハンバーグ)を500Wで加熱し、表面温度を
「上面の平均値」で測った実測データから求めたものです。

ワット数・経過時間・室温・初期温度も含めた5特徴量版を試したい場合:

```bash
python3 train_model.py --features watt elapsed_time_s ambient_temp initial_temp surface_temp_mean
```

## 実際に中心温度を予測する(predict.py)

`train_model.py` は「係数を求める」だけで、それ単体では中心温度は計算できません。
求めた係数を使って実際に予測するには `predict.py` を使います。

```bash
# 1. 学習(係数を計算し、model_coefficients.json を書き出す)
python3 train_model.py

# 2. 予測(新しく測った値を入れると中心温度が返る)
python3 predict.py --category hamburger_nichirei_mini --value surface_temp_mean=48.2
# => 推定中心温度: 60.5 ℃  (このモデルの学習時R^2=0.8582)
```

`--value` は `train_model.py` で使った特徴量と同じ名前を全て指定する必要があります
(過不足があるとエラーで教えてくれます)。ファームウェア側で直接計算したい場合は、
`model_coefficients_sample.h` の係数を同じ式(切片 + Σ係数×特徴量)に当てはめれば
C++でも同じ結果になります。ヘッダーには特徴量の並び順と単位(現状は全て℃)を
コメントで明記しているので、ハードウェア側で値を渡す際の単位・順序の
取り違えを防げます。`model_coefficients.json` 側にも同じ情報
(`feature_units` / `target_unit`)を含めています。

### あと何秒加熱すべきかを表示する(--target-temp)

まだ目標温度に届いていない場合、`--target-temp` を付けると「あと何秒加熱すべきか」も
表示します:

```bash
python3 predict.py --category hamburger_nichirei_mini \
    --value surface_temp_mean=48.2 --target-temp 85
# => 推定中心温度: 60.5 ℃  (このモデルの学習時R^2=0.8582)
# => 目標温度(85.0℃)まで、あと約20秒の加熱が必要と推定されます(...)
```

これは `train_model.py` が別途計算する「経過時間(elapsed_time_s)1秒あたり中心温度が
何度上がるか」という加熱速度(ハンバーグで約1.24℃/秒)を使い、
`(目標温度 - 現在の推定中心温度) ÷ 加熱速度` で逆算する簡易的な見積もりです。
加熱速度は加熱の全区間で一定と仮定した近似なので、目標温度に近づく(沸騰に近づく)
ほど実際には上昇が鈍る可能性がある点に注意してください。

## 対象食品を冷凍ハンバーグに絞った理由

複数の食品(コロッケ・ハンバーグ)に同時対応しようとすると、カメラでの食品認識・
食品ごとの係数管理など仕組みが複雑になる。発表までの期間が限られているため、
まずは**冷凍ハンバーグ(ニチレイ ミニハンバーグ)1種類に対象を絞り**、精度良く
動くものを実証する方針にした。製品情報(1個20g・6個入り・120g、パッケージ記載の
目安加熱時間)は `food_templates.py` の `FOOD_TEMPLATES` に登録済み。

コロッケのデータ・係数も引き続きCSVやコードには残っているので、将来対象食品を
増やす際は `--categories all` を指定すれば両方のモデルを再び扱える。

## 今後の改善点(引き継ぎ書より)

- `weight_loss_rate`(重量変化率)を実測データに追加すると、本来想定していた
  5特徴量フルのモデルが作れる。
- データ数(現在n=8)がまだ少ないため、追加データが増えるほど信頼性が上がり、
  複数の特徴量を安心して使えるようになる。
- 対象食品をハンバーグ以外にも広げる場合は、食品ごとに同様の実測データ収集と
  カメラでの食品認識の仕組みが必要になる。
